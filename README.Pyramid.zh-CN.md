# 苍穹战机 · Pyramid 联调版

## 打开游戏

设备地址：`192.168.1.100`；Laya 设备服务：`http://192.168.1.100:8010`。

电脑运行“一键启动Pyramid竞技.cmd”，进入 `http://127.0.0.1:8854/?pyramid=1#race`。该窗口通过独立桥接服务访问设备，游戏画面和物理仍运行在电脑浏览器。

解压本联调包后，同样运行“一键启动Pyramid竞技.cmd”。电脑需要 Python 3（本工作区启动器可使用已安装的 Codex Python）。不要只双击 HTML 来尝试硬件模式；离线 HTML 仍可使用本地规则 AI。

如设备 IP 改变，在 PowerShell 运行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\start-pyramid.ps1 -PyramidIP 新IP`。已有桥接进程的目标不会自动改写；更换 IP 前关闭旧桥接进程，避免端口冲突。

## 玩法与决策来源

- 对手选择“Pyramid NPU 协同”，检测连接后开始比赛。玩家手动驾驶，对手使用 NPU 战术选择；双方同种子、同装备、同生命，各 3 枚炸弹。
- 勾选“双方自动驾驶演示”后，两边各自请求 NPU 战术。网络返回时间可能不同，演示结果不保证平局。
- NPU 在“躲避、攻击、补给、保持”四种战术中选择。本地算法执行移动、短周期避弹和普通技能限制；这属于模型与算法协同驾驶。
- 面板显示 NPU 服务实际报告的推理耗时、浏览器端到端耗时、有效决策和失败次数。
- 每侧最多一个在途请求，约 150 ms 才发起下一次；800 ms 超时，超过 30 个游戏 tick 的旧答案丢弃。暂停、失焦、重赛和离开时取消旧请求。
- 请求失败或决策过期会标记“规则接管”。本局曾发生接管，结算与历史记为“混合练习”，即使服务后来恢复也保留该标记。完整使用 NPU 战术的对局标记“NPU 协同”；本地模式仍标记“本地规则 AI”。
- 方向键 / WASD 移动，自动射击，C 技能，X/B 炸弹，Esc/P 暂停。手机拖动玩家战场移动。右上角“返回首页”结束当前对局，已结算成绩保留。

## 个人关卡 AI 与速度档位

在右上角点击“返回首页”，展开左下角“个人关卡 AI 控制”。连接成功后选择敌机速度，点击“开始个人 AI 关卡”。也可在游戏中切换“Pyramid 自动驾驶”，关闭后恢复手动驾驶；面板提供暂停、继续和实时推理统计。个人 AI 演示不写入普通金币、成就和高分，联机合作仍使用手动控制。

个人关卡和同关竞技均支持 0.5×、1×、1.5×、2×、3×，开局前选择。同关竞技双方使用同一档位，仅改变敌机移动速度；敌方子弹、开火间隔、自机、补给下落和倒计时保持原速。竞技结算及历史记录保留速度档位。

补给目标按预计下落位置和自机到达时间选择。安全且靠近的补给可由本地拾取辅助接近，面板明确显示“本地拾取辅助”；危险或无法及时到达时优先避弹。补给计数包括各类补给，漏过包括掉出屏幕及关卡切换时未拾取的补给。

推理耗时衡量结构化游戏状态的战术决策，不是摄像头画面识别速度。速度档位用于观察更快敌机下的反应和生存表现。

## 设备部署与恢复

本次部署目录 `/root/sky-blaster-pyramid`，独立环境 `.venv`，模型 `models/Laya/multilingual`，服务日志 `service.log`。原系统的 Python 依赖保留。

服务当前为后台进程，尚未配置开机自启。设备重启后，可通过 SSH 登录后运行：

```bash
cd /root/sky-blaster-pyramid
.venv/bin/laya-axera serve --model multilingual=models/Laya/multilingual --host 0.0.0.0 --port 8010 --provider AxEngineExecutionProvider
```

这条命令在当前 SSH 窗口前台运行，关闭窗口会影响服务；保持窗口打开进行试玩。服务已在运行时不要重复执行。

部署脚本、原安装日志和真实验收记录保存在电脑工作区。源项目固定提交 `0e6e5398dc7b5977325f713621437c373d4695ef`，按 Apache-2.0 许可使用；本游戏保留上游 MIT LICENSE。设备下载使用项目文档列出的镜像，NPU 推理在 Pyramid 本机执行。

这是电脑浏览器连接 Pyramid 的联调版。尚未验证在 Pyramid 自身显示器上运行整个游戏，也不保证模型比本地规则算法或玩家分数更高。

## AI 决策框

Pyramid 同关竞技中，战场右侧显示“AI 决策框”；双方自动演示时，玩家席也有独立面板。个人关卡开启 Pyramid 自动驾驶后，右侧显示同样的框。点击标题可以展开、折叠，手机默认折叠。

面板区分 NPU 战术与本地实际动作，包括避弹、拾取辅助和进入散弹射程；方向、射击、C 技能、X/B 炸弹根据当帧输出输入点亮。这里是虚拟控制输入，射击仍受开火间隔限制，技能与炸弹仍受原游戏条件限制。暂停、阵亡或结束时按键全部熄灭，关闭个人自动驾驶后面板隐藏。

最近记录保留最多六次战术或按键变化，时间来自该局游戏时钟。NPU 等待及设备故障接管会明确标注，显示设备推理耗时与电脑端往返耗时。279 项测试、类型、修改文件规范检查及构建通过；真实设备浏览器验证双 AI、个人 AI、暂停清键、故障接管与手机布局，页面无脚本错误，记录为 previews/ai-decision-check.json。

## 死亡画面与散弹攻击修复

死亡后的竞技场景会冻结模拟，震屏计时也会冻结。现在仅在实际战斗状态绘制震屏，死亡等待画面与结算不再持续抖动。

AI 攻击站位根据当前武器调整。散弹使用与实际弹丸共享的 95 像素射程，靠近敌机下方，允许进入上半场，并用更短的移动预测周期调整距离。近处出现来袭子弹时中止靠近、优先避让。远程武器保持后方站位；这些规则同时用于个人关卡和同关竞技。发送给 NPU 的状态新增当前武器及射程，面板显示“进入散弹射程”。

277 项测试、类型、修改文件规范检查与构建通过。真实 Pyramid 的浏览器定向场景验证中，AI 实际捡到散弹后从 y=575 靠近至约 y=369，将静止测试敌机生命从 1000 打至 790，自身保持满血。玩家死亡等待期间观测 2358 帧结束文字位置稳定，双方死亡后也稳定，无页面脚本错误。此为定向回归场景，未用于估计胜率；记录为工作区 previews/death-shotgun-check.json。
